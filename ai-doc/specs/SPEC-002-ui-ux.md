# SPEC-002｜內部計算工作台 UI／UX 契約

文件狀態：`RD Implementation Ready`  
版本：`1.2`
日期：`2026-07-14`
權威範圍：資訊架構、畫面、狀態文案、CTA、RWD、accessibility 與 UI QC

## 1. UX Intent

- 使用者：鉦富已授權的內部計算使用者與規則管理者；同一位計算使用者可完成編製、覆核與核發。
- 使用情境：收到客戶資料後，可能只知道人數、面積、設備能力或舊版公升容量，需要快速得到可追溯結果。
- 使用者心智模型：選擇「我知道什麼、要算什麼」，再依提示補資料；不應先理解公式代碼。
- 主要任務：建立案件、完成至少一個有效計算軌、覆核並核發報告。
- 成功狀態：5 秒內知道案件狀態、哪一軌完成、下一步按什麼、有哪些限制。
- 自然下一步：資料不足就補任一可用軌；計算有效就由目前使用者進入覆核；覆核完成就預覽並核發，不需切換帳號。
- 最高風險誤解：把提醒當阻擋、把舊版公升數當現行能力、把設計需求計算誤認為產品或證書符合性判定。
- 高風險操作：啟用規則版本、核准 override、核發正式報告。
- 使用思考習慣：`#目的`、`#使用者視角`、`#可驗證性`、`#系統描繪`。

## 2. UX 原則

1. 主畫面先回答「我在哪裡、現在狀態、下一步、風險」。
2. 客戶任務名稱優先於公式與方法代碼。
3. 每一畫面只保留一個 primary CTA。
4. 非阻擋提醒不能使用禁止語意或讓 primary CTA disabled。
5. 技術細節、完整公式、來源 hash 與 raw trace 降層到 drawer／details／audit。
6. 現行與舊版視覺對稱，但單位、標籤、來源時效與限制必須明顯不同。
7. 正式核發前提供範圍摘要與報告預覽。

## 3. Information Architecture

| Route | 畫面 | 主要使用者 | Primary CTA |
|---|---|---|---|
| `/cases` | 案件清單 | 內部計算使用者 | `建立案件` |
| `/cases/new` | 任務與模式精靈 | 工程 | `下一步：填寫資料` |
| `/cases/{id}` | 案件工作台 | 內部計算使用者 | 依狀態顯示 `開始計算`／`開始覆核`／`繼續覆核` |
| `/cases/{id}/review` | 覆核工作台 | 內部計算使用者 | `完成覆核` |
| `/cases/{id}/report` | 報告預覽與版本 | 內部計算使用者 | `核發此版本` 或 `下載已核發報告` |
| `/rules` | 規則版本與來源 | 規則管理者 | `建立規則版本` |

首屏不常駐公式教學；每頁提供可鍵盤操作的 `查看計算依據` 或 `使用說明` drawer。

## 4. 案件清單

採表格／清單為第一視覺，不使用大型 KPI 卡。

欄位：案件編號、客戶、地點、任務、模式、計算狀態、生命週期、完成軌、最後更新、負責人、下一步。

Toolbar：搜尋、狀態、模式、任務、負責人、日期篩選；篩選結果與 URL query 同步。

點列開啟右側 drawer，顯示摘要、完成軌、提醒、最新報告與 audit；drawer 不推擠主清單。桌面 drawer 自行捲動，mobile 使用全寬 drawer。

Empty state：

> 目前還沒有案件。建立第一筆案件後，即可依人數、面積或設備能力開始計算。

Primary CTA：`建立案件`。

## 5. 建立案件精靈

### Step 1：你要解決什麼問題？

以五個任務卡呈現，不先顯示 T code：

- 我知道每日用餐人數，要換算流量。
- 我知道每日用餐人數，要規劃設計需求。
- 我知道廚房與用餐區面積，要換算流量。
- 我知道廚房與用餐區面積，要規劃設計需求。
- 我知道設備能力／有效容積，要反推等效人數及面積。

每卡只有一個 `選擇此任務` 動作。

### Step 2：選擇計算模式

- `現行 Q/G`：預設選中，短說明「現行方法的流量與油脂量設計需求」。
- `舊版 Q/V`：短說明「歷史指引有效容積換算，報告會標示時效」。
- `新舊雙軌`：短說明「兩軌分開計算；任一軌有效即可繼續覆核」。

完整法規說明放 drawer，不在卡片放長文。

### Step 3：案件基本資料

客戶、地點、案件名稱、用途、資料提供者與證據皆為選填，label 必須明示「選填」；空白資料不得阻擋建立案件。餐飲類型不在此步驟重複詢問，移至案件工作台的現行 Q/G 計算資料。

未填案件名稱時，後續清單與工作台以系統案件編號作顯示識別；未填客戶或地點時顯示「未填客戶」或「未填地點」，不得產生空白標題或無法辨識的列。

## 6. 案件工作台

### 6.1 頁面層級

1. 頁名與案件識別。
2. 狀態摘要：生命週期、計算狀態、目前完成軌。
3. Primary CTA。
4. 短風險／提醒。
5. 輸入與結果工作區。
6. 完整來源、公式與 audit drawer。

### 6.2 多軌 layout

桌面／laptop：現行與舊版使用兩欄或分段並列；欄位標頭固定顯示軌名、單位系統、來源地位、完整性 badge。

Mobile：垂直堆疊，不做左右比較表；完成軌置前，不足軌置後並保留 `補齊此軌`。

不得用顏色作唯一識別；軌名與文字 badge 必須存在。

### 6.3 動態輸入

只顯示所選任務與模式需要的欄位：

- 現行人數：每日用餐人數、餐飲類型、油脂／殘渣清除週期、實際使用時間（可選）。
- 現行面積：廚房面積、用餐區面積、餐飲類型、清除週期、實際使用時間（可選）。
- 現行反推：Q 設計能力、G 設計能力、資料來源／證據、餐飲類型與相同假設。
- 舊版人數：餐期、人數、q、t、exact k、聚合方式與理由。
- 舊版面積：面積、密度、翻桌率、q、t、exact k。
- 舊版反推：有效容積、q、t、k、密度、翻桌率。

每個數值欄位在 label 旁顯示單位；跨單位轉換需顯示轉換摘要。
餐飲類型不得在新案件頁預先代選；現行 Q/G 軌開始計算前，使用者必須在工作台明確選擇。

## 7. 計算結果

每一完成軌顯示：

- 結論數值與正確單位。
- 結果語意，例如 `現行設計需求 Q/G` 或 `舊版有效容積設計`。
- 控制條件。
- 採用規則版本與來源地位。
- `查看計算過程` drawer。

raw、source display、adopted value 可在 drawer 比較，主畫面只顯示 adopted value 與必要限制。

結果頁不顯示產品型號、證書或匹配狀態。限制摘要固定提供「本系統未執行特定產品或證書符合性判定」，完整說明降層至報告限制與方法 drawer。

## 8. Now What State Matrix

| State | 第一行可見文案 | Primary CTA | 次要／復原 |
|---|---|---|---|
| loading | 正在載入案件，完成後會顯示可執行的下一步。 | 無 | `返回案件清單`（逾時後） |
| empty inputs | 先填完任一可用軌的必要資料，即可開始計算。 | `填寫資料` | `查看必要欄位` |
| validation error | 請修正標示欄位後再計算；已填資料已保留。 | `前往第一個錯誤` | `查看全部錯誤` |
| BLOCKED | 目前無法計算：選定模式沒有有效結果。雙軌案件請先補齊任一軌。 | `返回補資料` | `查看兩軌缺口` |
| COMPLETE | 計算已完成；下一步由你進行工程覆核。 | `開始覆核` | `查看計算過程` |
| COMPLETE_WITH_REMINDER | 可繼續覆核：〔現行／舊版〕軌已完成。另一軌因缺少〔欄位〕未計算，不影響本次放行。 | `繼續覆核` | `補齊另一軌資料` |
| IN_REVIEW | 案件已進入覆核；你可以直接繼續，不需切換帳號或等待他人。 | `繼續覆核` | `返回案件清單` |
| returned | 覆核已退回。請依退回原因修正後重新提交。 | `修正案件` | `查看退回紀錄` |
| REVIEWED | 覆核已完成，可以預覽並核發此版本。 | `預覽報告` | `查看覆核紀錄` |
| ISSUED | 此版本已正式核發，不需再次核發。若內容要改，請建立新修訂版。 | `下載已核發報告` | `建立新修訂版` |
| SUPERSEDED | 此版本已被新版取代；請查看目前有效版本。 | `查看目前版本` | `下載歷史版本` |
| no permission | 你沒有執行此動作的權限；請聯絡對應管理角色。 | `返回安全頁面` | `查看所需角色` |
| runtime error | 目前未完成這次操作，已填資料仍保留。請重試或回到案件頁。 | `重試` | `返回案件頁`、`複製事件編號` |

技術 error code、API route、correlation ID 降層到 details；不得以 visible HTTP 4xx／5xx 當主要文案。

## 9. 覆核工作台

目前使用者依序看到：

1. 一頁結論與完成軌。
2. 非阻擋提醒與功能範圍限制。
3. 輸入、假設與證據。
4. 每一步計算、來源與規則版本。
5. override、來源例外與差異。
6. 報告預覽。

Primary CTA：`完成覆核`。次要動作：`退回修正`。

頁面固定顯示短提示：「本案件可由同一位使用者完成編製、覆核與核發；系統會分別保存每個責任步驟。」不要求角色切換或另一人登入。

完成覆核前必須勾選：已確認方法、單位、來源、限制及未完成軌標示；這是具名 review checklist，不使用散落 checkbox。

退回需填人類可理解的原因，並顯示工程人員下一步。

## 10. 報告預覽與核發

核發前顯示 preview summary：案件、revision、模式、完成軌、未完成軌、提醒、編製／覆核 actor、報告頁數／產生狀態與快照 hash 短碼。

Primary CTA：`核發此版本`。核發屬正式紀錄，需確認 modal：

> 核發後此版本與快照不可修改。若內容變更，需建立新修訂版。

確認按鈕：`確認核發`；取消：`返回預覽`。不要求輸入長字串確認。

## 11. 規則管理

### 規則版本

清單顯示 code、version、來源、狀態、有效期、checksum、回歸結果。ACTIVE 版本不提供編輯，只有 `建立新版本`。

啟用前顯示參數差異、受影響方法與回歸結果；未通過時 `啟用版本` disabled 並顯示原因。

## 12. Responsive 與 scroll owner

必測 viewport：`1440×900`、`1024×768`、`390×844`。

- 1440：完整清單、雙欄結果、右側 drawer。
- 1024：維持可比較欄位；必要時結果改為上下區塊，不得水平裁切主要 CTA。
- 390：表格改 stacked list，drawer 全寬；所有主要流程可完成，不要求水平捲動。
- 同畫面最多一個主要垂直 scroll owner；drawer 開啟時 drawer body 自行捲動並阻止 scroll chaining。
- 固定底部 CTA 不得遮住欄位、錯誤或鍵盤輸入。

## 13. Accessibility

- 所有 input 有可見 label、程式化關聯與就近 error。
- 完整鍵盤操作；focus order 與畫面順序一致。
- focus ring 可見；drawer／modal 開啟時 focus trap，關閉後回原觸發點。
- `Escape` 關閉暫時 drawer／popover／modal；正式輸入不因 Escape 丟失。
- 狀態不只靠色彩；文字與 icon 共同表達。
- 一般文字與控制項符合 WCAG AA 對比。
- 計算完成與錯誤使用適當 live region，但不重複朗讀整頁。

## 14. Visible Error Gate

任何 critical route 若可見以下內容，UI QC 失敗：

- `.inline-error`／`[role=alert]` 中未處理 runtime 錯誤。
- `HTTP 4xx/5xx`、`Not Found`、`Internal Server Error`。
- 可見 `/api/...` route 或 stack trace。
- 載入失敗但沒有重試／安全返回。

Build、lint、unit test 不能取代真實瀏覽器驗證。

## 15. UI Acceptance Criteria

| ID | 驗收條件 | Auto evidence | Manual evidence |
|---|---|---|---|
| UX-001 | 5 秒內知道頁面、狀態與下一步 | heading／CTA smoke | 5 秒理解紀錄＋截圖 |
| UX-002 | 每個主要狀態只有一個 primary CTA | DOM role count | 截圖 |
| UX-003 | COMPLETE_WITH_REMINDER 的 `繼續覆核` 可用 | E2E state assertion | 文案與 CTA 截圖 |
| UX-004 | BLOCKED 僅在零有效軌發生 | integration＋E2E | 兩軌缺口畫面 |
| UX-005 | 未完成軌無假數值、明示未計算 | DOM text／absence assertion | 結果截圖 |
| UX-006 | 同一帳號可從計算一路完成覆核與核發，過程不要求切換身分 | E2E actor assertion | review／report 流程截圖 |
| UX-007 | 首屏不常駐完整公式教學 | DOM text budget | 首屏與說明 drawer 截圖 |
| UX-008 | 高風險動作有 preview／confirmation | E2E | modal 文案截圖 |
| UX-009 | 1440、1024、390 無重疊、裁切、非預期 overflow | screenshot suite | QC 逐頁目視 |
| UX-010 | critical routes 無 visible runtime error | DOM sweep | 瀏覽器／network evidence |
| UX-011 | 鍵盤、focus、label、錯誤關聯可操作 | accessibility scan | keyboard script 紀錄 |
| UX-012 | 未登入、session 過期或無權限時提供安全返回／重新登入，不洩露案件內容 | E2E authorization states | restricted 畫面截圖 |

任何 UI 實作未經實際瀏覽器、viewport 與 Now What matrix 驗證，只能判定 `未充分驗證`。
