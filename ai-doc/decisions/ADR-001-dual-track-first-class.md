# ADR-001｜不同算法依據採雙路徑一級功能

狀態：Accepted

日期：2026-07-13

決策來源：HD-01、HD-02、HD-05

## Context

客戶案件可取得的資料與設計需求不同。本系統同時支援兩份算法依據：內政部《建築物給水排水設備設計技術規範》附錄 5，以及臺北市政府工務局衛生下水道工程處《油脂截留器使用維護及設計說明》。兩份來源的單位與計算語意不同，必須分開計算與呈現。

## Options

- A：只做內政部給排水規範（附錄 5）。
- B：只做臺北市工務局衛工處設計說明。
- C：兩份算法依據都是一級功能，共用案件治理但隔離計算。
- D：只做其中一份，另一份延後或以人工附件處理。

## Decision

採 C。

## Chosen rule

- 模式固定為 `CURRENT_QG`、`LEGACY_QV`、`DUAL_COMPARISON`。
- 新案件預設 `CURRENT_QG`，工程人員可明確選其他模式。
- 兩軌使用不同 calculator、參數命名空間、單位、run、結果語意與報告章節。
- 五個任務在兩軌都必須獨立可用。
- 不建立第三套混合公式，不自動取兩軌較大值，不因缺資料靜默降級。
- 對外報告以「算法依據」及來源文件名稱標示，不使用新舊、現行、過往等方法稱呼；兩份結果不得混用單位或互相代填。

## Consequences

- 需要兩套版本化參數與回歸測試。
- 資料模型必須區分 L/min、L/h、Veff、Q 設計能力與 G 設計能力。
- 報告與 UI 增加雙軌分欄，但能消除人工重算與語意混用。

## Compatibility

本 ADR 延續並取代專案外 v0.1～v0.4 中散落的雙軌描述。本專案的 SPEC-001 是工程權威來源；任何程式或後續規格若與本 ADR 衝突，必須建立明確後繼 ADR。

## Terminology Update｜2026-10-01

依使用者要求，對外報告與系統文案統一以「算法依據」稱呼來源文件及算法 A／B。此修訂只統一顯示名稱，不改變兩條計算路徑、公式、參數或資料契約。
