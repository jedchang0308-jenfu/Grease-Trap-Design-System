# ADR-010｜直接產出正式報告，不建立核發流程

狀態：Accepted / Implemented Locally

日期：2026-09-14

決策來源：使用者明確要求取消核發機制，任何使用者都可產出正式報告；正式報告編號必須與案件編號共用同一套邏輯。

## Context

現行匿名共享系統已能保存報告草稿 snapshot 並在本機產生 PDF，但介面沒有正式報告出口。產品不需要送審、覆核、核准人、角色或核發狀態；這些流程只會增加操作與資料模型負擔。

## Decision

- `/cases/:id/report` 同時提供「產生草稿 PDF」與「產生正式報告」。
- 所有可使用案件的匿名使用者都能直接產出正式報告，不檢查角色或權限。
- 尚未保存草稿時，正式報告動作先保存當下 snapshot，再由同一 snapshot 產生正式 PDF。
- 草稿不配置正式報告編號；正式報告才顯示報告編號與版次。
- 正式報告直接沿用案件編號 `GTC-YYMMDD-00`，不得另加 `RDR-` 前綴或建立第二套轉換、日期、流水號邏輯。
- 正式報告版次直接使用案件修訂號，例如案件修訂 1 顯示「修訂 1」，檔名使用 `R01`。
- 正式報告不建立送審、覆核、核准、核發或新的 lifecycle state，也不建立獨立報告 collection。
- 舊 `ISSUED`／`SUPERSEDED` 資料仍維持歷史唯讀相容。

## Consequences

- 正式報告與草稿使用相同計算結果、來源、輸入與版面，只有文件狀態、正式編號及版次呈現不同。
- 案件與正式報告共用唯一主編號，不需要轉換或第二組流水號交易，也不會失同步。
- 此正式報告是使用者直接產出的編號文件，不宣稱另有身分驗證、簽核或不可變稽核鏈。

## Supersedes

本 ADR 取代 ADR-009 中「介面只能使用報告草稿、不得提供正式報告輸出」的限制；ADR-009 的匿名共享、Firestore 與靜態部署邊界仍有效。本 ADR 也明確不恢復 ADR-005 的核發流程。
