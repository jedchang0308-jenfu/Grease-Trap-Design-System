# ADR-002｜雙軌任一有效軌即可放行

狀態：Accepted  
日期：2026-07-13  
決策來源：HD-06，使用者明確要求「雙軌只要有一軌資料足夠，就要可放行，系統僅作提醒即可」

## Context

實務案件常只有一軌資料足夠。若要求兩軌都成功才允許覆核，另一軌的資料缺口會不合理地阻擋已可成立的工程計算；若系統靜默忽略不足軌，使用者又可能誤認已完成雙軌比較。

## Options

- A：兩軌都有效才可進入覆核與核發。
- B：任一軌有效即可放行；另一軌以非阻擋提醒明示。
- C：自動降級成單軌且不揭露。

## Decision

採 B。

## Chosen rule

| 有效軌數 | 案件狀態 | 報告草稿／覆核／核發 |
|---:|---|---|
| 2 | `COMPLETE` | 可建立報告草稿；送審後可覆核，核准後可核發 |
| 1 | `COMPLETE_WITH_REMINDER` | 可建立報告草稿；送審後可覆核，核准後可核發 |
| 0 | `BLOCKED` | 不可覆核或核發 |

- 每一要求軌都產生 `TrackAssessment`。
- 只有有效軌建立 `CalculationRun`。
- 未完成軌顯示「未計算」、缺少欄位與原因，不建立假結果。
- `COMPLETE_WITH_REMINDER` 的主要 CTA 固定為 `完成報告草稿`；送審後才進入最終覆核，補齊另一軌是次要選項。
- 核發報告標示「雙軌案件—單軌完成」，不得宣稱已完成雙軌數值比較。
- 放行只判斷計算軌是否成立；產品型號與證書匹配不在系統範圍內，不能成為阻擋條件。

## Consequences

- orchestrator 必須隔離每軌交易與錯誤。
- API 要回傳每軌狀態與 0～2 個 run IDs。
- UI、報告與 QA 都要覆蓋一軌成功的正向流程。
- 仍維持完整追溯與工程覆核，不降低成功軌的計算標準。

## Compatibility

本 ADR 是對 v0.3「任一軌失敗即 PARTIAL 且不得核發」的 `Intentional replacement`，並延續 v0.4 的後繼規則。`PARTIAL` 不得重新出現在公開狀態列舉中。
